# 协作研究写作 · 中文使用说明

中文名：**协作研究写作**　机器名（slug）：`content-research-writer`

## 什么时候调用它

当你希望以“对话式协作”而不是“一次性生成”的方式写东西时：

- 想先聊清楚选题、读者和目标，再一起搭大纲；
- 希望研究材料随查随登记、引用随用随挂；
- 想打磨开头钩子，拿到 2–3 个不同风格的候选自己选；
- 写完一节就得到一节的反馈（清晰度、连贯性、证据、风格）；
- 在意“稿子读起来像我自己写的”，要求编辑只给选项、不替你改定。

在中文环境直接说中文名即可触发，例如：

> “用**协作研究写作**帮我写一篇关于 X 的文章，先别动笔，先问我问题。”

## 与三个主栈的关系

它是**横向能力**，可被三个栈技能在相应阶段调用：

| 主栈 | 典型调用点 |
| --- | --- |
| `tech-blog-en`（英文技术博客） | 选题访谈、协作列纲、钩子候选、逐节反馈、作者声音保持 |
| `dev-post-zh`（中文社区文章） | 研究后追问澄清、分段协作、多视角反馈 |
| `deep-research-report`（行业深研报告） | 研报叙事段的列纲与可读性反馈（数据与论证仍走证据台账流程） |

## 三条中文使用纪律

1. **证据不落地到台账，就不算研究完成**：该技能负责协作与写作，
   所有来源必须同时写入 `source_registry.csv`，主张写入 `claims_registry.csv`
   （规范见套件根目录 `references/evidence-ledger-spec.md`）。
2. **编辑只给选项和理由，最终句子作者拍板**；对中文稿尤其要防止“翻译腔改写”，
   作者说“这就是我的风格”时保留原句。
3. **交付止于本地文件**：产出 `final.md`（或 HTML）。上传到任何平台由你本人手动完成，
   套件不提供也不会尝试任何平台登录或自动发布。

## 最小起步

```text
1. 让我先回答它的 6 个 intake 问题（主题/读者/篇幅/目的/已有素材/风格）
2. 一起定 outline.md，并在每节标出证据状态
3. 逐节写作、逐节要反馈
4. 研究材料同步登记到 source_registry.csv
5. 全文评审 → 过对应主栈的 preflight 质量门 → 本地交付
```
