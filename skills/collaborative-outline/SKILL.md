# 协作列纲（collaborative-outline）

## 触发
研究材料基本就位、准备开写；或作者已有草稿但结构混乱需重构。

## 输入
冻结的 brief、研究台账（或素材清单）、作者偏好的结构范式。

## 步骤
1. **骨架四件套**：钩子、张力、核心论点、结尾路径；全部来自作者意图，AI 只负责追问与提议。
2. 切节：每节一个目的（证明论点的一个侧面），标注证据状态
   （有据：列 claim id / 待证：列补证任务 / 纯论述）与预计篇幅。
3. 中文长文额外要求前 3 行钩子与平台排版节奏（见 `../../references/platform-adaptation.md`）。
4. 处理分歧：给出 2–3 种结构方案并说明取舍（叙事线 vs 论证线、归纳 vs 演绎），作者拍板。
5. 争议性主题必须包含“反方与局限”节。
6. 落盘 `outline.md`（模板 `../../templates/outline.md`），作者确认即**冻结**；
   之后要改骨架必须回到作者重新确认，写作中不得偷换论点。

## 输出契约
- 作者签字的骨架四件套 + 节级大纲（含证据状态与篇幅）。

## 质量门 OUTLINE GATE（阻断项）
- 核心论点与 brief 不一致；存在“待证”节但没有补证计划；
- 每节篇幅加总与目标篇幅严重失衡且无取舍说明；骨架未经作者确认。

## 不做什么
- 不在列纲阶段写完整正文；不替作者决定叙事立场；不允许通过堆并列小节掩盖没有主线。
