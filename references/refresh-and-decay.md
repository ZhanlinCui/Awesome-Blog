# 旧文更新与衰减检测规范（Article Refresh & Decay）

旧文维护 = 一次“带记忆的重写”。不凭感觉改，先做衰减盘点，再过同样的质量门。

## 1. 衰减信号盘点（逐条标注）

| 信号类别 | 检查内容 |
| --- | --- |
| 数据衰减 | 文中统计值、价格、市场规模、份额是否已有更新口径 |
| 版本衰减 | 软件版本、API、参数、弃用特性、依赖最低版本 |
| 政策/标准 | 法规、标准、合规要求是否变化 |
| 生态格局 | 公司/产品/收购/停服、竞争格局变化 |
| 链接衰减 | 外链是否失效；来源是否撤稿/勘误 |
| 结论有效性 | 核心论点在新证据下仍成立 / 部分变化 / 已被推翻 |

每条标注：**仍成立 / 已变化 / 已失效**；变化与失效项必须关联新的 source_id。

## 2. 更新工作流
1. 复制旧稿建立工作目录，保留旧稿快照；
2. 跑 `scripts/preflight.py` 对旧稿体检，列出失效链接、`[需补]`、版本号；
3. 针对“已变化/已失效”项重新研究取证（走 research-evidence 同一套台账）；
4. 在大纲层决定：局部修订 / 结构性重写 / 发布续作并互链；
5. 正文修订后，**重新过事实核查门与 preflight 门**，标准与新稿相同；
6. 文首可加“更新说明”：更新日期、更新了什么、哪些结论被修正（诚实披露）。

## 3. 不做什么
- 不静默改掉旧结论：凡结论被修正，必须在更新说明中告知；
- 不为“显得新”而把仍有效的内容重写一遍；
- 不在没有新证据时更新数字；
- 更新稿同样止于本地文件，作者手动处理平台侧操作。
