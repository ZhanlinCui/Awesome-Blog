# 平台内容适配规范（仅本地排版适配，不涉及发布动作）

本文件只定义“同一篇稿子在不同平台读者习惯下的**本地稿件格式**差异”。
最终产物永远是本地 Markdown/HTML；**登录、上传、发布一律由作者本人手动完成，
套件不提供任何自动化能力，也不处理任何账号凭据**。

## 适配维度对照

| 维度 | 微信公众号深度文 | 知乎长文 / 回答 | 开发者社区（如掘金/CSDN/思否等的通用习惯） |
| --- | --- | --- | --- |
| 标题 | 可适度悬念化，但不做标题党；主副标题常见 | 问题导向、结论可前置 | 技术关键词明确，突出问题与方案 |
| 篇幅 | 2500–6000 字常见 | 800–5000 字，重论证与证据 | 1500–6000 字，代码占比高 |
| 开头 | 场景钩子、口语化前 3 行留人 | 先给结论/立场，再展开 | 背景 → 问题 → 方案三段式 |
| 段落 | 短段（1–4 行），善用小标题分隔 | 可稍长，重逻辑层级 | 短段 + 列表 + 代码块混排 |
| 代码呈现 | 少而精，关键片段；注释用中文解释 | 可贴完整代码并逐段解释 | 完整可运行片段 + 运行结果 + 环境说明 |
| 图表 | 必须真实插入图片文件，禁止 `[图X]` 占位 | 图/表配结论句 | 架构图/流程图优先 Mermaid 或真实图片 |
| 英文术语 | 首次出现给中文解释，避免夹杂 | 保留通用英文术语，必要时中英对照 | 保留原名（API、库名不翻译） |
| 结尾 | 观点收束 + 讨论引导 | 明确回答问题 + 可操作建议 | 总结 + 局限性 + 延伸阅读 |

## 硬性纪律
1. 只产出 `deliverables/<platform>-final.md`（或 .html）；不存在“发布到平台”的步骤。
2. 不出现任何登录、Cookie、凭据、自动上传的脚本、命令、配置样例或教程。
3. 配图必须是真实文件引用（相对路径或作者确认的图床链接），不得留 `[图X]`/`[示意图]` 占位。
4. 平台名称只用于描述读者习惯，不暗示任何官方合作或背书。
