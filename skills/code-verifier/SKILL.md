# 代码可运行校验（code-verifier）

## 步骤
1. 提取全部代码块（按语言、按顺序编号），标注声明用途与预期输出。
2. 在隔离/临时环境执行：优先容器或一次性虚拟环境；安装步骤本身也要验证。
3. 记录到 `verification_log.md`：操作系统/运行时版本、依赖与版本、执行命令、
   实际输出（节选）、退出码、日期；与文中输出逐字比对。
4. 不一致即提 **Blocker**：以实际输出为准修文，或以文中目标为准修代码后重跑。
5. benchmark：复现实验 ≥ 设定次数，记录硬件、配置、冷热启动、原始数值与统计方式。
6. 无法运行（需硬件/账号/付费服务）时：要求文中显式写明“未经运行验证”、
   原因、以及作者做过的替代验证（静态推演/官方文档依据），否则 BLOCKED。
7. 安全检查：示例命令不得含破坏性操作未警告；密钥/内网地址/个人数据不得出现在样例中。

## 意见分级（内部使用，不构成任何发布效果承诺）
- Blocker：跑不通、输出造假、危险命令未警告。
- Major：环境前提缺失、版本不明导致大概率失败。
- Minor：可读性/健壮性问题。 Nit：措辞与注释。

## 输出契约
- verification_log.md；分级意见清单；通过/阻断结论。

## 不做什么
- 不凭“看起来对”跳过运行；不伪造输出；不修改受保护文本来迁就失败的代码
  （正确方向是修代码或显式标注）。
