# 质量门（Quality Gates）总则

本文件定义 Awesome-Blog 套件统一的质量门模型。三个栈技能（tech-blog-en / dev-post-zh /
deep-research-report）与所有子技能都遵循同一套规则：**阶段不过门，产物不向下游流动**。

> 重要声明：本套件出现的任何分数（百分制或分级）都是**本地内部启发式检查**，
> 用于帮助发现写作与事实质量问题，**不构成对搜索引擎排名、引用流量、传播效果或任何商业结果的承诺**。

## 1. 门的四档结论

| 结论 | 含义 | 允许的动作 |
| --- | --- | --- |
| PASS | 全部必检项满足 | 进入下一阶段 |
| PASS-WITH-NITS | 必检项满足，仅剩措辞类建议 | 可进入下一阶段，建议项记录备查 |
| BLOCKED | 存在至少一个阻断项 | **禁止进入下一阶段**；退回责任阶段修复后重新过门 |
| NEEDS-HUMAN | 机器无法判定，必须作者本人决策 | 作者显式签字（在产物中写明决策）后才可放行 |

## 2. 阻断项（任何阶段命中即 BLOCKED）

1. **虚构引用**：出现无法在来源登记册中定位的引用、链接、书名、论文、访谈或数据。
2. **虚构数字**：正文中的精确统计值、金额、比例、版本号、性能数字没有来源或没有复算记录；
   作者未提供时必须保留 `[需补：数字及来源]` 占位，而不是猜一个数。
3. **代码不可验证**：技术文中的代码/命令未经实际运行或未经静态推演确认；
   无法运行时必须显式标注“未经运行验证”及原因。
4. **口径不一致**：同一指标在不同段落使用了不同定义、单位、币种、基期或统计范围且未说明。
5. **关键事实零独立印证**：支撑核心结论的关键事实只有单一来源，且未按规则降级表述。
   注意：聚合商与其转述的原始出处**不构成**两个独立来源。
6. **研究痕迹泄漏**：成稿中残留内部 claim ID、本地文件路径、台账文件名、审计标签、
   `[CITATION NEEDED]` 之外的内部批注。
7. **越界主张**：技术文给出未经论证的医疗/法律/投资结论；研报给出确定性买卖建议。
8. **平台发布动作**：套件任何环节不得尝试登录或发布到内容平台；最终产物只能是本地文件。

## 3. 各阶段质量门速查

| 阶段 | 必检项（不过即 BLOCKED） |
| --- | --- |
| 选题简报 | 读者画像、阅读场景、读者读完能获得什么、不回答的问题，四项齐全 |
| 研究取证 | 每条关键 claim 有来源 ID；来源登记册字段完整；聚合与原始出处已区分 |
| 大纲 | 核心论点一句话可复述；每节标注证据状态（有据/待证/纯论述）；作者确认骨架 |
| 分段写作 | 数字锁定（无来源不写具体数）；代码块可运行或显式标注；占位符统一为 `[需补：…]` |
| 事实核查 | claim–source 审计通过；反证尝试已记录；争议数字有多源或区间表述 |
| 技术校验 | 代码实际运行通过，或不可运行的原因与替代验证方式写明 |
| 编辑润色 | AI 腔清单逐项检查；术语一致性；中文稿无不必要的中英夹杂 |
| SEO/GEO | 标题/描述/结构完整；关键词自然出现而非堆砌；所有优化建议标注为启发式 |
| 发布前检查 | preflight 脚本 0 阻断项；研究痕迹清除；许可证/图片来源合规 |
| 旧文更新 | 衰减项逐条标注“仍成立/已变化/已失效”；变化项给出新证据 ID |

## 4. 分数怎么用

- 百分制 rubric 只用于**自我比较**（同一篇文章改稿前后的相对变化）和**决定是否放行**。
- 分数不是质量的客观真值，更不是平台排名预测；任何对外材料中不得宣称“达到 X 分就能获得流量”。
- 默认放行线由各栈自行规定，且必须允许作者在记录理由后手动覆盖
  （覆盖记录留在工作台账，不进入成稿）。

## 5. 反例（这些做法不算过门）

- 把“搜索到了类似说法”当成印证：两个互相转载的页面仍是一个来源。
- 用“据行业报告显示”但不写具体哪份报告、哪一年、哪一页。
- 为了让 preflight 通过，删掉 `[需补]` 占位而不是补上证据。
- 用模型生成一段“看起来合理”的参考文献列表。
- 因为“时间紧”跳过代码运行直接宣称已验证。
